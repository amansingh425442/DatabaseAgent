# Project decisions

## Inspection and authority

At initial inspection, the workspace was empty and no AGENTS.md or raw Olist CSVs were present. The supplied handoff is authoritative and retained in HANDOFF.md. The initial CSV contract was provisional and small synthetic fixtures supported correctness testing.

The original public Olist archive was subsequently downloaded from the official Kaggle dataset endpoint. All nine actual CSV headers match the importer contract. The 44,717,580-byte archive has SHA256 `967e41e04fc306fe604e2a693f488995a8b41e5047418f8a5c8e4abd6deca784`; ignored `data/raw/download_manifest.json` records source URLs and archive/file hashes. The full import committed 1,550,922 rows, including 99,441 orders, with zero rejected rows and zero skipped duplicates. The 261,831 identical geolocation rows were retained as separate source occurrences. Independent CSV-versus-database checks confirm all nine table counts and business aggregates; the local evidence is in `.runtime/source-inspection.json`, `.runtime/import-report.json` and `.runtime/import-verification.json`. Synthetic fixtures remain separate from the real database. The user subsequently selected a free Gemini API model and supplied a private local key.

The existing commerce-agent environment was inspected first: Python 3.11.16, LangChain 1.4.3, Sentence Transformers 5.7.0, Pandas 3.0.6, Pydantic 2.13.5, Plotly 6.9.0, Streamlit 1.65.0. SQLAlchemy 2.0.54, psycopg 3.3.6 and pgvector 0.5.0 were added. Unrelated inherited packages remain installed but are not used. VS Code interpreter configuration targets commerce-agent. After the user supplied their Gemini key, langchain-google-genai 4.4.0 and its dependencies were installed with the existing dependency closure constrained. PostgreSQL, LangChain and other established versions were preserved.

Docker Desktop cannot start on this computer because WSL is unavailable. The local database therefore uses official PostgreSQL 16.15 Windows binaries and pgvector 0.8.6 built from its official source with the existing Visual Studio C++ compiler. The server binds to `127.0.0.1:55432`, uses SCRAM authentication and keeps its cluster in `.runtime/postgres-data`. Setup preserves existing data; start/stop commands manage the local server without deleting the cluster. The imported data survived a graceful stop and restart. Docker Compose remains an alternative on a machine with a working engine. Native download/build provenance is recorded in `.runtime/postgres-provenance.json`.

## Data and metric contracts

Separate raw, analytics, knowledge and app schemas isolate imported records, approved views, document vectors and history. Orders/items/payments use validated natural keys; reviews/geolocation use content fingerprint plus occurrence because review IDs and ZIPs need not be unique. Exact repeated source rows are retained for those two tables, while re-importing the same file does not duplicate them. Files are imported in dependency order with foreign keys and nonnegative money/integer checks. No relationship requiring complete category translations is enforced. Existing keys are never overwritten by the append-only importer.

Bulk import uses a reusable parameterized PostgreSQL insert statement and SQLAlchemy's batched execution, with conflict handling and returned keys for accurate import counts. Invalid rows can still be isolated individually. This avoids constructing a large new SQL statement for every batch and made the full geolocation import practical without changing append-only or validation behavior.

Metrics are versioned project definitions, not assertions of Olist business policy. All purchase dates use half-open filters. Order-level metrics support calendar-year grouping and a validated discrete `years` list. The compiler returns integer years in chronological order and binds year filters as integers. A 2016-versus-2018 comparison excludes 2017 even when date bounds span all three years. Category year grouping is outside the current contract; payment shares still require payment-method grouping. Default status scope is all recorded statuses, including canceled/unavailable; item sales therefore means recorded item prices, not recognized revenue. Delivered metrics explicitly use delivered status. Monetary currency is original BRL. Missing categories are Unknown; untranslated categories retain the source category. Null monetary values are excluded from sums and exposed as missing counts; AOV counts all matching placed orders, including those without item amounts. See src/olist_agent/analytics/metrics.py for each grain, status/date/currency/null/denominator/attribution field.

Payments and items are separately aggregated to the order grain before joining. Category sales use item prices only. Payment shares explicitly distinguish records, value and orders; order shares overlap and cannot be pie-charted. Purchase-to-customer-delivery duration excludes missing/negative durations; late rate compares actual to estimated timestamp only for delivered orders with both fields. Source timezone is unresolved: no conversion or confirmed timezone claim. Date coverage and partial boundary months are reported, not synthesized. Refunds, profit, traffic, device/marketing and causal drivers are unavailable.

## Agent and query boundaries

A single tool-calling create_agent produces Pydantic Report output with ToolStrategy. A small importable model factory keeps providers replaceable. Seven tools retrieve contexts, inspect approved views, fetch definitions by ID, validate model SQL, propose its execution, inspect stored results and validate ChartSpec. Time/call limits, failed-call fingerprints and model-call ceilings stop loops. Middleware checks fatal budget state outside tool error handling. Retrieved passages are evidence; only the model-authored SQL passing validation and explicit approval can execute. Executable Python is never accepted. Essential definitions remain deterministic rather than relying solely on similarity.

The concrete Gemini adapter selects the Developer API rather than Vertex AI. Current model is gemini-3.1-flash-lite: it responded to an authenticated generation probe after gemini-3.8-flash returned high-demand 503 responses and gemini-3.7-flash timed out. This remains a free-tier model choice; no billing settings were changed. Low reasoning effort, a 30-second request timeout, no automatic provider retries, bounded output and hidden thought content fit the existing agent budget. Streamlit defers loading local embedding weights until retrieval is used and caches them across subsequent questions. Provider failures receive safe, actionable UI messages; raw error payloads and credentials are withheld.

On 6 October 2026 the user explicitly requested Gemini-authored SQL instead of structured query templates. Gemini now receives the actual column-level approved schema and metric/relationship documentation, and writes a complete PostgreSQL SELECT. SQLGlot 30.21.0 parses and validates exactly one SELECT, including read-only CTEs, joins, subqueries and window functions. All physical relations must be explicitly qualified approved analytics views; lexical CTE scopes and column qualification are checked. Writes, multiple statements, SELECT INTO, locks, recursion, external relations, unsupported casts and side-effect functions are rejected. Invalid proposals return feedback to a non-executing validation tool for model repair. Validation uses a copied AST and never rewrites executable SQL. Import credentials remain outside tool services. Execution uses read-only transactions, a pg_catalog search path, statement timeouts, server-side streaming and row/byte caps. The exact approved SQL is sent through the driver without bind interpretation, preserving literal percent signs and colons. Legacy templates remain available only to CLI/fixture services and old saved results. Decimal evidence remains exact.

Every chat analytics call now uses LangChain's built-in HumanInTheLoopMiddleware with an isolated in-memory checkpoint through create_agent. The complete model-written SQL is validated offline and displayed verbatim, including comments and quoted text. A session-bound, single-use approval token and an execution grant bind approval to the exact SQL, presentation metadata and fetch limit. Each query in a multi-call turn is reviewed individually; no batch executes until all are approved. Rejection cancels the investigation without resuming the model. Additional queries pause again. Active execution time and thread call budgets carry across resumptions; human review time is excluded. No custom agent graph or new infrastructure is introduced. Query execution no longer makes a second, unreviewed dataset-coverage read.

The earlier template-based ScopeMiddleware has been removed from the agent. Intent parsing supplies chart permission, a question-scope hint and eligibility for grounded result completion; it does not construct or replace SQL. Gemini is instructed to respect requested dates, years and filters, including discrete 2016-versus-2018 comparisons. SQLValidationMiddleware checks safety and routes invalid proposals to validation feedback before the existing HITL review. It does not invent a replacement SQL query or bypass approval. Syntactic/scope validation is not a proof of semantic correctness, so the user must review the generated SQL and its evidence.

ResultCompletionMiddleware finishes clear supported calendar summaries directly from actual approved result rows, without requesting another model response. The presentation layer formats exact values, attaches the supporting table, and validates any requested Plotly chart against those saved rows. Missing years are disclosed rather than plotted as invented zeros. General investigations retain the agent workflow and grounded recovery after a provider failure. Both middleware components use the standard create_agent interface rather than a custom graph.

The minimal UI keeps only chat, chart permission, sessions, history, SQL review and approve/reject controls. Completed and rejected reviews persist with report history. Pending checkpoints and the browser's session selector are in memory; server or browser-session restarts discard pending approvals safely. Metadata/history and retrieval queries remain necessary internal reads and are distinct from the business SQL being reviewed. The human SQL CLI continues to execute SQL explicitly supplied by the person invoking it.

Results and reports are addressed by session+result IDs, with app-role RLS policies using a transaction-scoped session capability. This initial local Streamlit interface has no identity/authentication layer and is not a deployment-ready tenant security system. RLS reinforces service isolation but the app role remains trusted to set the capability. Reports store concise activity and retrieved citations, not private reasoning.

## Retrieval and charts

all-MiniLM-L6-v2 was chosen as a small public local embedding model with 384 dimensions; construction verifies this contract. The database uses pgvector exact cosine search because the corpus is small. Source-grounded metric/schema/join/example/coverage documents have deterministic IDs, provenance, version, text, content hashes and embedding model metadata. Bounded overlapping word chunks prevent excessively long passages. Content/model changes are reindexed; dimension changes need migration.

Chart specifications never contain executable Python. Plotly renders stored rows after validating session/result/column references and semantic units. Lines require ordered axes; pies require a complete non-overlapping meaningful total. Unknown/null measures, excessive categories and unsuitable plots fail clearly. No uncomputed Other group is invented. Positive graph/chart requests turn the UI toggle on; explicit negative instructions take priority. Preferences are enforced independently of model output. Chart-only follow-ups reuse previous approved saved rows without another data query or model call. Changed dates, filters or metrics require a fresh model-authored query and approval. There is no hidden template fallback that repairs a semantically incorrect model query.

Actual Gemini browser chat first verified a placed-order count of 99,441 against stored PostgreSQL evidence. The subsequent year-comparison browser check verified 329 orders in 2016 and 54,011 in 2018, excluded 2017, and rendered a bar chart whose values matched the original CSV. Calendar-year totals describe the records available: coverage starts in September 2016 and ends in October 2018, so these are partial boundary years and do not establish complete annual demand or growth. Results cited by findings/charts are included in the table list after validation, so a model cannot accidentally hide its cited table by omitting Report.tables. Broader natural-language routing accuracy still requires comparison with displayed evidence.
